# MaixCAM2视觉功能接入设计（用户确认并修订）

日期：2026-10-14。用户已确认先输出状态和串口，新增要求云端对话与视觉互斥、摔倒检测常驻。以下为实施依据；硬件验证仍待接线。

## 目标与现有功能保护

在sample_project中接入外部MaixCAM2的双模式视觉程序。KEY1短按进入行人红绿灯检测，长按退出；KEY2短按进入行人方位检测，长按退出。两个视觉模式互斥，启动默认IDLE。短按另一键直接切换模式；长按只退出对应的当前或待进入模式，避免误退出另一模式。拟采用30ms消抖、持续按住2秒触发一次长按，长按释放不再触发短按。

保留KEY0云端对话、音频、Wi-Fi、MPU6050摔倒任务、DTU定位和邮件业务。按最新要求增加前台互斥：KEY0进入对话前等待视觉IDLE确认，KEY1/2进入视觉前等待云端音频通道关闭、采播停用；摔倒检测不属于前台互斥范围，持续采样。Wi-Fi连接、按键扫描和通信管理后台可常驻，但不能在未选中的业务内继续采播或推理。视觉不复用DTU串口，不引入ESP32屏幕或板载摄像头。现有KEY0事件算法保留，入口转交统一调度器。

## 实现方案比较

1. 推荐：沿用现有ASCII CRC16协议，ESP32新增独立视觉服务，共享现有XL9555读数。改动小，可与已安装视觉程序兼容。
2. 不采用：把独立esp32_example直接替换main。会丢失现有业务，且参考工程的GPIO按键与实物不一致，长按也未实现。
3. 不采用：重做两端协议或将推理搬入ESP32。增加回归范围，现有模型和MaixCAM2程序不需要更换。

## 分层与数据流

保持BSP → Middlewares → App。新增BSP/Vision串口配置与初始化；Middlewares/Vision提供纯C组帧、CRC和协议状态机；App/Vision负责请求、结果快照、超时和事件分发。云端板级适配只负责共享XL9555句柄及新增按键事件，不管理视觉协议。

按键扫描不阻塞等待模型加载，只提交最新请求；单一视觉任务拥有UART收发和会话状态。结果快照通过受保护接口读取，包含mode/state/count/left/center/right/valid和接收时间。切换、退出、断线和FAULT立即令旧结果无效。

UART未配置时按键请求返回明确的未配置状态，不声称模式已进入；允许宿主测试与协议模拟，不用日志串口冒充业务串口。

## 通信与恢复

沿用protocol.py的CRC-16/CCITT-FALSE、最长160字节行、0.5秒残包超时、分包粘包处理。ESP32启动SYNC，收到HELLO后建立新会话；MODE请求使用递增seq，20秒ACK超时，同seq最多发送3次。切换中拒收旧结果，收到匹配seq/mode的ACK后才接受对应epoch的RES，拒收重复及倒退frame。

HELLO重启、FAULT、超时和ERR撤销结果。有效结果超过1秒未更新即失效并重新同步；加载期间使用ACK超时，不能误用1秒运行超时。通信重连应回到IDLE，等待用户重新短按，不自动恢复旧绿色结果。快速按键和退出请求保留最新意图；新会话的握手不得无条件覆盖用户在握手期间提交的请求。

严格检查字段数、ASCII、数字范围、合法mode/state及人数语义。LIGHT和IDLE人数必须为0；PERSON的人数及各方向字段须与现有视觉端的999截断规则兼容。识别unknown/ambiguous/none不得解释为道路安全。

## 输出范围（用户确认）

当前模型仅识别行人，提供左/前/右相对摄像头方位，不识别车辆、台阶等全部障碍，不提供距离。红绿灯模型识别行人灯，不输出“可以安全过街”。

本轮只输出结果状态和UART0日志，不增加语音播报。新增统一前台服务，CloudAI仅通过控制/停止确认接口接入，避免组件循环依赖。启用视觉UART后，无法确认MaixCAM2回到IDLE时禁止开启对话；UART未配置时视觉永不启动，KEY0仍可用。视觉长按退出只退出对应当前/待选模式，KEY0长按只退出当前/待选对话。
