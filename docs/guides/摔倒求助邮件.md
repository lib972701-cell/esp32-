# MPU6050 摔倒求助邮件

本项目在 ESP32-S3 固件内完成采样、疑似摔倒判断、DTU 校时、LBS 定位与 QQ SMTP 邮件发送，无需电脑参与业务。

代码保持原有三层：`BSP/MPU6050` 是硬件驱动，`Middlewares/FALL` 是纯 C 算法，`App/Service` 组织采样和求助任务，`App/Boot` 组织配置与启动校准，`App/Message` 构造正文。公共传感器数据类型在 `BSP/MPU6050/include/imu_types.h`，BSP 不依赖算法层。详见 `工程分层.md`。

```mermaid
flowchart LR
    A[MPU6050 加速度与角速度] --> B[125 Hz 采样与静态校准]
    B --> C[冲击候选与姿态变化验证]
    C --> D[疑似摔倒事件]
    D --> E[有界事件队列]
    E --> F[唯一 DTU worker]
    F --> G[校时与 LBS 定位]
    G --> H[TLS 与 QQ SMTP]
    H --> I[紧急联系人邮箱]
```

## 接线与启动

| 设备 | ESP32-S3 引脚 | 说明 |
| --- | --- | --- |
| MPU6050 SDA | GPIO4 | I2C0，400 kHz |
| MPU6050 SCL | GPIO5 | AD0 低时七位地址 0x68 |
| DTU RX | GPIO17 | ESP32 TX 接 DTU RX |
| DTU TX | GPIO18 | ESP32 RX 接 DTU TX |

模块与 ESP32 共地，I2C 信号使用 3.3 V 电平与对应上拉；模块供电遵循所用板卡规格。启动时保持 MPU6050 静止，每次校准 2 秒，最多尝试 5 次。无稳定校准窗口时保留原驱动的未校准运行行为并告警。IMU 不响应时暂停判断，每秒尝试恢复；不自动扫描或重分配 GPIO，避免干扰 DTU 引脚。

上电装载 `private/mail_config.h` 中的发件邮箱、SMTP 授权码、收件邮箱及 DTU 时区配置，并初始化 DTU、校时；不会发送上电测试邮件。旧的 `MAIL_BOOT_ENABLE` 不再控制业务启动。授权码不输出到日志，但仍会编译进固件。

## 判定与发送

复用 `fall_detect` 的 MPU6050 驱动、姿态滤波、校准与纯 C 判断算法。应用配置沿用源项目默认调参：冲击候选为 2.5 g 或 120 度/秒，重力方向变化要求 30 度，验证窗口 3 秒；具体阈值可在 `menuconfig` 的 Fall detection 菜单调整。

疑似摔倒成立后立即入队，不等待原来的 15 秒取消窗口。每次事件后保留 5 秒抑制窗口；原动作持续静止不会反复触发。采样侧仅处理传感器与事件投递，不等待定位、网络、TLS、SMTP。DTU worker 是唯一 UART1 业务所有者，控制台操作与告警均通过该任务串行执行。

邮件主题为“【紧急求助】疑似摔倒”，正文请求联系人尽快联系本人确认安全，无法联系时安排现场查看，并附事件编号、开机后事件发生毫秒数、位置查询完成 UTC Unix 时间及可用 WGS84 坐标。位置为查询时的 LBS 基站估算，不应视为事件瞬间的精确位置。定位无效仍发信并明确注明，不复用旧坐标。

仅明确失败 `MAIL_FAILED` 重试，最多 3 次，间隔 5 秒、15 秒。`MAIL_REJECTED`、`MAIL_UNKNOWN`、`MAIL_ACCEPTED` 均不重发。日志 `FALL_MAIL_RESULT ... result=DATA_ACCEPTED` 表示 SMTP 服务器接受正文，不能据此声称联系人已阅读或已收到收件箱邮件。

## 队列与边界

DTU 任务队列容量 16；采样侧另保留最多 16 个待入队事件，锁争用或任务队列暂满时继续尝试入队。采样侧缓冲也满时明确记录 `FALL_NOT_QUEUED`，不报告成功。当前队列仅驻留 RAM，断电或重启会丢失待处理事件。缺少有效邮箱配置、无法获得有效时钟或 TLS 校验失败不会伪报发送成功。

本次未导入源项目模拟通知通道，也不将模拟通道的返回值当作真实发送结果。原算法的手持模拟数据调参不等于人体摔倒识别准确率；移植后的板上检测和真实收件效果需实机验证。

## 验证与运行

```powershell
powershell -ExecutionPolicy Bypass -File scripts/test.ps1
powershell -ExecutionPolicy Bypass -File scripts/build.ps1 -Reconfigure
```

测试涵盖原邮件协议、定位、时间与辅助工具回归，以及移植的摔倒算法、求助策略测试和新增邮件正文/重试测试。构建产物为 `build/main.bin`。刷入完整构建后观察 `FALL_QUEUED` 与对应 `FALL_MAIL_RESULT`，核对事件编号、邮件内容与邮箱收件。测试可用安全的设备模拟动作，不要通过人体真实摔倒验证。
