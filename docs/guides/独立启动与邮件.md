# 独立启动与邮件

当前版本上电后加载本地编译配置，由唯一DTU worker初始化UART1并查询网络时间，转换为UTC；**不发送上电测试邮件**。疑似摔倒事件或明确的控制台命令才会请求邮件。云端对话通过Wi-Fi启动，KEY0短按开启、长按退出；检测持续独立运行。

## 私有配置

本机 `private/mail_config.h` 包含邮箱、SMTP授权码、启动开关和DTU时间时区。目录列入gitignore，示例位于 `components/App/Boot/mail_config.example.h`，没有真实凭据。配置由Boot层读取，不打印到日志。

凭据编译进本地固件；`mail_clear`只清运行RAM，下次启动会重新加载。修改私有配置后需要重新构建和烧录，首次创建时应使用 `-Reconfigure`。没有私有配置时使用Boot/Defaults的禁用模板。不要将含凭据的固件或构建产物公开。

当前集成版：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build-cloud.ps1 -Reconfigure
```

原5.1.2邮件/摔倒版使用 `scripts/build.ps1 -Reconfigure`。两种构建的输出目录和SDK配置独立，详见[工程分层](../architecture/工程分层.md)。

## 时间与运行

DTU `config,get,nettime` 返回的本机网络时间实测为UTC+8，原TIME模块减去480分钟转换为UTC。云端语音新增Wi-Fi SNTP，在没有有效系统时间时校时，避免依赖DTU链路；小智服务端Unix时间也保持UTC，不叠加显示时区。

没有有效时间时不放弃TLS证书日期校验。检测任务不会等待邮件初始化、定位或TLS；原求助邮件只对确定失败进行有界重试，提交结果未知时不自动重发。

脱离电脑仍需要开发板和DTU各自正确供电。只读电脑日志不参与设备业务；不要拔掉唯一供电后期待设备继续运行，也不要随意并联电源正极。

## 实测与历史

2026-10-14集成版已验证按键云端对话、持续检测和对话期间模拟摔倒求助邮件实收，见[上机验证](../verification/hardware_cloud_20261014/上机验证记录.md)。

2026-10-12曾按当时版本演示“每次上电一封定位测试邮件”，用户确认完全脱离电脑的冷启动实收。该历史启动发信行为已被当前“不发上电测试邮件”的业务替代；机器证据保留在 `verification/autonomous_20261012`。一次实收不代表长期可靠性或定位精度。
