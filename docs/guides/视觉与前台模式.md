# 视觉与前台模式

外部MaixCAM2识别结果先输出UART0日志和状态，不增加视觉播报。UART接线尚未确定，默认禁用；源码/构建通过不等于双板联调通过。

## 按键

| 按键 | 短按并释放 | 持续按住2秒 |
|---|---|---|
| KEY0 | 选择Wi-Fi云端对话 | 退出当前/待启动对话 |
| KEY1 | 选择行人红绿灯LIGHT | 退出当前/待启动LIGHT |
| KEY2 | 选择行人方位PERSON | 退出当前/待启动PERSON |

短按另一键直接切换。长按只退出对应业务，不退出其他键选中的业务；长按松手不产生短按。30ms消抖，开机按住、I2C失败、多键同时按下均抑制事件，确认释放后重新武装。BOOT不替代这些按键。

KEY0/1/2分别为XL9555 P1_7/6/5，输入寄存器0x01的bit7/6/5，低有效；共享现有I2C0 GPIO41/42和地址0x20。KEY1/2不是直接连接ESP32 GPIO的按键。

## 互斥和常驻检测

前台选择只有IDLE、CLOUD、LIGHT、PERSON。进入视觉时先撤销对话代次、停采播、清队列，等待音频通道关闭确认，才发送LIGHT/PERSON；进入对话时先发送视觉IDLE，收到匹配请求号的ACK后才开启对话。快速切换保留最新意图，迟到的旧连接/ACK不能启动旧业务。

启用UART后，MaixCAM2未回应IDLE就不能证明识别已停止，因此不启动对话。MODE每20秒重发，同seq最多发送3次；超过后取消前台意图并重新同步。重启、FAULT或有效结果超过1秒未更新时取消旧业务、撤销旧结果并同步，恢复后重新短按。模型加载期间使用20秒ACK超时。

按键扫描、UART管理、Wi-Fi配网/连接及音频管理后台可常驻；未选中的对话不采播，视觉IDLE释放相机/模型。后台常驻不是两个业务同时运行。

MPU6050采样、摔倒算法和求助队列开机独立运行。调度器没有暂停/删除fall_app的接口；原DTU worker仍独占UART1，定位、TLS及邮件业务不改。

## 接线未定时

默认两种构建配置均为：

```text
# CONFIG_VISION_UART_ENABLE is not set
CONFIG_VISION_TX_GPIO=6
CONFIG_VISION_RX_GPIO=16
```

KEY0仍可用。KEY1/2会退出旧对话并显示UART_UNCONFIGURED，不发送命令或假称进入识别。长按对应视觉键退出，或短按KEY0恢复对话。

若启用UART却GPIO无效/驱动安装失败，没有远端IDLE确认就不启动对话。日志显示UART_WRITE_FAILED；修正配置或关闭视觉UART后重建，不绕过互斥。

## 确定接线后的配置

最新映射：ESP IO6/P1-3 TX→Maix A22 RX，ESP IO16/P1-6 RX←Maix A21 TX，GND共地；IO7保留IMU INT。配置已填TX6/RX16，但UART仍禁用，未烧录。驱动拒绝GPIO7，接线前须确认IO16无外部占用及不接RGB屏/ESP板载摄像头。下方此前GPIO7建议已被此条替代。

接线更正：用户指出IO7接着IMU INT，保留该接线，不再将IO7作为视觉RX。下方此前IO6/IO7推荐已撤回，需核对另一空闲RX脚再配置；Maix仍UART4 A21/A22，ESP UART仍禁用。

2026-10-14用户最终指定Maix侧面1.25mm六针UART4：[接线说明](视觉串口接线建议.md)。ESP32 IO6/TX→Maix A22/RX，ESP32 IO7/RX←Maix A21/TX，GND共地。Maix正式应用已更新/dev/ttyS4并释放默认监听，设备IDLE运行/UART4打开已验证，恢复自启；ESP配置仍禁用，实际接线后再启用和验证双板通信。

1. 核实两板实际引脚、电平、供电和占用，TX交叉RX、GND共地。本指南没有替用户确定引脚。
2. 当前语音集成版在sdkconfig.cloud设置CONFIG_VISION_UART_ENABLE=y并填写实际TX/RX，同步sdkconfig.cloud.defaults。UART2固定115200、8N1、无流控。
3. 不能占用DTU GPIO17/18、IMU GPIO4/5、I2C GPIO41/42、音频GPIO3/46/9/10/14及日志/USB/PSRAM等保留脚。驱动检查已知占用，外部占用仍需核实。
4. MaixCAM2正式应用/maixapp/apps/vision_modes/settings.py配置UART_DEVICE/UART_PINMAP，保留INITIAL_MODE=IDLE。实际UART设备名由MaixCAM2接口和系统占用决定，不等同ESP32的UART2；旧/root/vision_modes副本不是正式应用。
5. 配置后重启正式应用，核验SYNC/HELLO/IDLE ACK，再测试按键、云端连接中切视觉、视觉加载中快切、拔线、单端重启和切换期间模拟摔倒。

## 状态和串口调试

原UART0控制台115200输出日志；业务UART2只传协议包，不混入调试文字。

```text
activity_status
activity_select idle
activity_select cloud
activity_select light
activity_select person
```

activity_select走与按键相同的调度器。状态包含desired、phase、remote/confirmed、cloud_requested/cloud_stopped、uart_configured/error、结果valid/state、人数和接收年龄。CLOUD_REQUESTED表示提交了对话请求，尚未联网时不代表已经录音；cloud_stopped包含采播和通道关闭确认。

格式示例（不是实机证据）：

```text
activity: desired=PERSON phase=SWITCHING remote=IDLE error=none
vision: mode=PERSON state=person count=2 L/F/R=1/0/1 epoch=3 frame=42
vision: RESULT_INVALID; state=unknown
```

结果通常5Hz。LIGHT状态red/green/unknown/ambiguous；PERSON状态person/none/unknown、L/F/R为相对摄像头左/前/右，可同时出现多个方向。无效结果显示unknown，不继续输出旧人数。none不能解释为无障碍或道路安全；模型仅识别人，不提供距离，绿灯结果不等于可以安全过街。
