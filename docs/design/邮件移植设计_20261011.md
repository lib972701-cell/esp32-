# ESP32-S3 串口 4G 邮件移植

用户已授权实现电脑测试链路的 ESP32 版本；不增加服务器、PPP、Wi-Fi 或整机业务。
目标 ESP-IDF 5.1.2 / esp32s3，板手册 DNESP32S3 V1.0。

数据路径：SMTP/MIME → mbedTLS（证书链、smtp.qq.com 主机名及有效期）→ UART1 → DTU TCP → QQ SMTP465。
DTU沿用已实测参数版本5；模块SSL关闭。软件先检查通道附加数据，避免污染TLS。
每次手动连接前重启DTU，等待重新联网建立新的TCP连接。失败不自动重发，DATA发送后未得到最终答复标记UNKNOWN。

UART1候选 GPIO17 TX/P1-7、GPIO18 RX/P1-8，115200 8N1、不假设RTS/CTS。
用户确认尚未接线、没有LCD；摄像头也必须不连接。实际DTU TX须确认3.3V或适配电平。
UART0用于USB_UART调试台；默认业务串口不启动，执行mail_wiring_ok确认接线后启用。

单个邮件工作任务独占UART1/TLS；调试台只排队一次请求。配置仅RAM保存、授权码无回显、不写NVS。
用户通过本地辅助脚本安全输入邮箱和授权码，设置当前UTC时间供证书有效期验证。
没有可信时间时拒绝TLS。提供probe（不认证、不发信）、send_test、status、clear命令。
仅固定中文测试邮件，明确并非真实求助；后续整机可调用异步请求API，不在本任务加入跌倒检测或GNSS。

验证：先以宿主C测试SMTP碎片/多行、字段注入、错误与UNKNOWN；再ESP-IDF实际编译。
硬件未连接，不宣称烧录、TLS握手或ESP32邮件实收通过。电脑已收到邮件不等同本固件验证。
