# 视觉接入实施计划

实施方式：当前会话直接实施。用户已确认设计并指定状态/串口输出、前台互斥、摔倒常驻；依据现有授权继续，不重复请求开始工作的许可。

目标：KEY0对话、KEY1红绿灯、KEY2行人方位统一调度，停止旧业务后开启新业务。技术：ESP-IDF5.4/FreeRTOS、纯C可测试状态机、现有CRC16协议。设计依据：docs/architecture/视觉功能接入设计_20261014.md。

约束：不改变DTU/邮件/定位/摔倒算法与引脚，不增加播报、屏幕或板载摄像头；UART2默认未配置，未接线不烧录。当前工作区包含用户此前未提交成果，直接在用户指定目录增量修改并记录哈希，不切换/重置工作区或提交已有改动。

## 审查重点

1. 串口断线时远端仍可能推理，不能把本地无结果当作远端停止。
2. OpenAudioChannel可能阻塞；停止意图必须使旧连接完成后无法重新采播。
3. 快速LIGHT→CLOUD→PERSON只执行最新意图，错误/重启取消旧结果。
4. UART未配置时不能误占UART1或UART0，KEY0应保留可用。
5. 人数总和按999截断，序号和frame需与Python端的31位范围兼容。
